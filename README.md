# 這是一個關於資料庫課堂實作的IT報修與案件追蹤系統

使用原生 PHP 與 MySQL 開發的 Web 應用程式，模擬客戶提交報修需求，以及工程師分類、處理與追蹤案件的工作流程。

本專案著重於表單驗證、登入身分管理、關聯式資料庫操作與案件處理歷程，並逐步抽離共用程式，改善維護結構。

目前為本機開發與展示用途，未導入企業正式使用。

## 功能

### 客戶報修
- 填寫案件標題、日期與問題描述。
- 填寫報修單位、聯繫人與聯繫資訊。
- 填寫期望完成日期。
- 表單輸入驗證。
- 送出成功後，顯示案件編號。

### 工程師帳號
- 使用姓名、Email 與密碼建立帳號。
- 透過註冊開關與工程師註冊碼限制帳號建立。
- 使用 Email 與密碼登入。
- 登出並清除登入 Session。
- 限制未登入者存取工程師管理頁面。

### 案件管理
- 顯示最近 100 筆案件。
- 查看案件完整內容與客戶聯絡資訊。
- 於詳細頁設定單別：報修、保養、安裝。
- 更新案件處理狀態。
- 已完成案件以綠底標籤顯示。
- 列表呈現最後修改工程師與紀錄時間。
  
### 處理歷程
- 新增本次處理內容與工時。
- 記錄操作工程師。
- 記錄單別與狀態的變更。
- 查詢歷次處理紀錄與累計工時。
- 使用資料庫交易整合案件更新與歷程新增。

## 操作流程

```text
客戶提交報修單
        ↓
案件建立，單別尚未設定
        ↓
工程師登入並查看案件列表
        ↓
進入案件詳細頁
        ↓
設定單別、更新狀態、填寫處理內容與工時
        ↓
保存處理歷程
        ↓
案件列表顯示最新狀態與最後修改工程師
```

## 安裝與啟動

### 1. 取得專案

下載原始碼，或複製此儲存庫至本機。

### 2. 匯入資料庫

在 MySQL 建立專案資料庫，並匯入資料表結構。

- 資料庫名稱：待填
- SQL 結構檔位置：待填

SQL 檔應包含完整建表順序、索引與必要預設資料，不包含真實客戶資料或正式帳號。

### 3. 設定資料庫連線

依本機環境設定 `db.php`，提供 PDO 連線變數 `$pdo`。

需確認：

- 主機與連接埠。
- 資料庫名稱。
- 本機資料庫帳號與密碼。
- 連線字元集。

不要將正式環境的資料庫密碼提交至公開儲存庫。

### 4. 啟動網站

將專案放入本機 Web 伺服器的網站目錄，啟動 Web 伺服器及 MySQL。

例如專案資料夾為 `it_helpdesk`、網站使用預設連接埠時：

```text
http://localhost/it_helpdesk/ticket_create.php
```

工程師登入入口：

```text
http://localhost/it_helpdesk/login.php
```

實際網址依本機網站目錄與連接埠設定調整。

### 5. 建立本機測試工程師

依 `register.php` 的實作：

1. 暫時開啟工程師註冊。
2. 設定非公開的隨機註冊碼。
3. 建立測試帳號。
4. 關閉註冊並清除設定中的註冊碼。
5. 使用新帳號登入。

註冊碼僅用於授權建立工程師帳號，不等於 Email 所有權驗證。

## 資料表概覽

| 資料表 | 用途 |
| --- | --- |
| users | 工程師姓名、Email、密碼雜湊、角色與啟用狀態 |
| tickets | 案件內容、客戶聯絡資訊、單別與目前狀態 |
| ticket_work_logs | 操作工程師、處理內容、工時及單別／狀態變更 |

### 關係說明

- 一筆案件可以有多筆處理紀錄。
- 每筆處理紀錄保存操作工程師 ID。
- 查詢時透過工程師 ID 取得姓名。

以上為資料邏輯關係；實際外鍵限制以 SQL 結構檔為準。

## 設計重點

### 單別與問題類別分開

- 問題類別：電腦、網路、帳號、軟體等問題領域。
- 單別：報修、保養、安裝等服務性質。

客戶建立案件時不指定單別，由工程師在詳細頁確認後設定。

### 最後修改工程師不等於負責工程師

列表中的「最後修改工程師」取自最新一筆處理紀錄。

此欄位表示最後留下紀錄的人，不代表案件已指派給該工程師。

### 案件與歷程一起保存

更新案件與新增歷程放在同一筆資料庫交易中，避免案件資料已更新，但處理歷程未保存。

### 共用程式整理

將工具函式、Session／CSRF 初始化與登入檢查集中管理，減少各頁重複程式。

## 資料驗證與安全處理

依實際完成版本確認以下項目：

- 密碼以雜湊保存，不儲存明碼。
- SQL 輸入參數使用 PDO 參數化查詢。
- HTML 輸出使用 htmlspecialchars() 跳脫。
- 修改資料的表單驗證 CSRF token。
- 管理頁面檢查工程師登入身分。
- 登出使用 POST，並清除 Session 與 Session Cookie。
- 後端檢查必填欄位、長度與資料格式。

Email 格式或 DNS 檢查不代表信箱存在，也不代表使用者擁有該信箱。

以上為已採用機制的說明，不代表系統已通過完整安全稽核。
